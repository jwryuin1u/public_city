# 재고배분 실행·검증 목업

고객에게 TO-BE의 사용 흐름을 직접 보여주기 위한 클릭형 목업이다. 실제 배분 프로그램은 돌지 않는다. 화면의 숫자와 상품은 모두 가상이며, 화면 위쪽에도 "목업 · 숫자는 모두 가상"이라고 표시된다.

## 구성

| 경로 | 내용 |
| --- | --- |
| `index.html`, `index_v2.html` | 목업 본체 두 버전. 브라우저로 열면 된다 (설치·서버 불필요, 인터넷 불필요) |
| `dummy-data/` | 시연할 때 화면에 올리는 더미 파일. `generate.py`로 다시 만들 수 있다 |
| `operate.js` | 시연 시나리오를 자동으로 조작해 화면을 저장하는 스크립트 (`node operate.js`) |
| `walkthrough/` | 자동 조작 결과: 단계별 화면 28장, 전체 과정 영상 `demo.webm`, 질문·답변과 재테스트만 담은 영상 `demo_질문답변.webm` |

## 두 가지 버전

| 버전 | 파일 | 자동 조작 결과 | 차이 |
| --- | --- | --- | --- |
| 처음 버전 | `index.html` | `walkthrough/` | 기능 확인용. 동작이 즉시 끝난다 |
| 디자인 개선 버전 | `index_v2.html` | `walkthrough_v2/` | 기능은 같다. 색과 간격, 문구를 다듬었고 동작마다 짧은 로딩이 있다 |

디자인 개선 버전에서 바꾼 것:

- 배경과 카드를 무채색으로 바꾸고 강조색은 주요 버튼에만 쓴다
- 상태 표시를 색 알약에서 "점 + 글자"로 바꿨다. 실행·버전·질문 번호는 고정폭 글씨다
- 간격을 4px 단위로 맞추고 글씨 굵기를 줄였다
- 파일 선택 버튼을 한글로 바꿨다 (처음 버전은 브라우저 기본 영어 버튼)
- 문구를 다듬었다: 초기화, 실행 조건, 수량이 달라진 상품, 질문 보내기, 답변 저장, 파일에서 답변 읽기 등
- 건수 차이에 기준을 붙였다: "비교 대상 대비 +15", "직전 운영 대비 +9"
- 로딩: 버튼을 누르면 0.3~0.9초 동안 처리 중 표시가 나오고, 실행은 4단계 진행 막대로 약 4초 동안 보여준다 (실제 약 6분)

시연 순서와 더미 파일은 두 버전이 같다. 아래 시연 순서의 화면은 처음 버전의 것이고, 개선 버전의 같은 화면은 `walkthrough_v2/`에 같은 파일 이름으로 있다. 개선 버전을 다시 조작하려면 `node operate.js v2`를 실행한다.

## 목업에서 실제로 동작하는 것과 흉내만 내는 것

| 구분 | 내용 |
| --- | --- |
| 실제 동작 | 재고 파일 올리기(S6): 올린 CSV를 브라우저가 실제로 읽어 컬럼 72개의 이름·순서, 카테고리 6개, 점 10개를 확인한다 |
| 실제 동작 | 화면 이동, 역할 전환, 상태 변화(등록됨 → 검증 중 → 승인 대기 → 운영), 승인 전 내려받기 차단, 파라미터 범위 확인 |
| 흉내 | 프로그램 실행과 결과 숫자. 버전과 파라미터에 따라 미리 정한 규칙으로 가상 숫자를 만든다 |
| 흉내 | 프로그램 파일 검사와 마스터 시트 검사. 파일 이름으로 판정한다 (`문법오류`, `규칙위반`, `운영본`, `시트누락`이 들어간 이름) |
| 실제 동작 | 질문 목록 내려받기와 답변 파일 올리기(질문·답변): 내려받은 CSV의 '답변 선택', '답변 내용' 칸을 채워 올리면 실제로 읽어 반영한다 |
| 흉내 | 이상치 6건과 질문 문안. 미리 정해 둔 표본이다. 실제로는 검토리포트의 경고와 결과 비교에서 뽑는다 |
| 흉내 | 질문 보내기. 실제 발송은 없고 상태만 '보냄'으로 바뀐다 |
| 흉내 | 내려받는 결과 파일. 엑셀 대신 작은 CSV가 내려온다 |
| 없음 | 로그인, 자동 수집, 알림. 화면 위의 "보는 역할"로 역할별 화면만 볼 수 있다 |

"처음 상태로" 버튼을 누르거나 새로 고치면 처음으로 돌아간다. 저장되는 것은 없다.

## 질문·답변 흐름에서 논의할 점

이 부분은 컨셉을 보여주기 위해 임의로 정한 것이 많다. 논의해서 정해야 할 것은 다음과 같다.

| 논의할 것 | 목업에서 임의로 정한 것 |
| --- | --- |
| 무엇을 이상치로 볼 것인가 | 과다 이동, 이동 건수 이상(검토리포트의 경고 2종), 미충전, 전일 대비 급변, 운영 버전과의 차이 |
| 누구에게 물을 것인가 | 프로그램·설정에 관한 것은 작성자, 점의 수요·사정에 관한 것은 그 점의 바이어 |
| 질문 문안을 어떻게 만들 것인가 | 이상치 종류별 정해진 문안. LLM으로 문안을 만드는 방안은 고객 PPT의 "LLM 서비스 연계"와 닿아 있어 논의 대상이다 |
| 어떻게 보내고 받을 것인가 | 화면에서 직접 답하거나, 질문 목록 파일(CSV)에 답을 적어 다시 올린다. 메일·메신저 발송은 흉내만 냈다 |
| 답변을 어떻게 분류할 것인가 | 정상 / 이동 제외 / 파라미터 조정 / 로직 수정 / 기타. 자유 서술만으로는 자동 반영이 어려워 선택지를 뒀다 |

| 이동 제외를 어디에 남길 것인가 | 그 재테스트에만 적용. 계속 적용하려면 MD가 제외·전용 SKU 마스터에 반영 |
| 바이어가 이 시스템에 로그인하는가 | 화면에는 "바이어" 역할을 넣었다. 로그인 없이 파일이나 메일로만 주고받는 방식도 가능하다 |
