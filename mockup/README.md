# 재고배분 실행·검증 목업

고객에게 TO-BE의 사용 흐름을 직접 보여주기 위한 클릭형 목업이다. 실제 배분 프로그램은 돌지 않는다. 화면의 숫자와 상품은 모두 가상이며, 화면 위쪽에도 "목업 · 숫자는 모두 가상"이라고 표시된다.

## 구성

| 경로 | 내용 |
| --- | --- |
| `index.html` | 목업 본체. 브라우저로 열면 된다 (설치·서버 불필요, 인터넷 불필요) |
| `dummy-data/` | 시연할 때 화면에 올리는 더미 파일. `generate.py`로 다시 만들 수 있다 |
| `operate.js` | 시연 시나리오를 자동으로 조작해 화면을 저장하는 스크립트 (`node operate.js`) |
| `walkthrough/` | 자동 조작 결과: 단계별 화면 22장과 전체 과정 영상 `demo.webm` |

## 목업에서 실제로 동작하는 것과 흉내만 내는 것

| 구분 | 내용 |
| --- | --- |
| 실제 동작 | 재고 파일 올리기(S6): 올린 CSV를 브라우저가 실제로 읽어 컬럼 72개의 이름·순서, 카테고리 6개, 점 10개를 확인한다 |
| 실제 동작 | 화면 이동, 역할 전환, 상태 변화(등록됨 → 검증 중 → 승인 대기 → 운영), 승인 전 내려받기 차단, 파라미터 범위 확인 |
| 흉내 | 프로그램 실행과 결과 숫자. 버전과 파라미터에 따라 미리 정한 규칙으로 가상 숫자를 만든다 |
| 흉내 | 프로그램 파일 검사와 마스터 시트 검사. 파일 이름으로 판정한다 (`문법오류`, `규칙위반`, `운영본`, `시트누락`이 들어간 이름) |
| 흉내 | 내려받는 파일. 엑셀 대신 작은 CSV가 내려온다 |
| 없음 | 로그인, 자동 수집, 알림. 화면 위의 "보는 역할"로 역할별 화면만 볼 수 있다 |

"처음 상태로" 버튼을 누르거나 새로 고치면 처음으로 돌아간다. 저장되는 것은 없다.

## 시연할 때 강조할 점

- 0813 사고(부분 추출)가 S3와 S6 두 곳에서 막힌다. 결과 파일이 아예 만들어지지 않는다
- 현업이 파라미터를 바꿔 돌려도 운영값은 그대로다
- 검증 결과는 TEST_가 붙어 ERP에 올릴 수 없고, 운영 결과는 승인 전에 내려받을 수 없다
- 프로그램을 바꾸는 일은 회귀 테스트와 IT혁신팀 승인을 거친다. 잘못되면 이전 버전으로 되돌린다
- 재고처럼 자동 수집이 아직 안 되는 원천은 파일을 올리는 것으로 같은 흐름에 들어온다
