# 재고배분 실행·검증 — 사용 흐름 안내

재고배분 프로그램을 등록해 실행하고, 결과를 검증·승인한 뒤 ERP 업로드 파일을 받는 흐름을 화면 순서대로 설명한다.

| 파일 | 내용 |
| --- | --- |
| `index_mvp.html` | 화면. 브라우저로 열면 된다 |
| `walkthrough_mvp/demo.webm` | 전체 흐름 영상 (실제 사용 속도) |
| `walkthrough_mvp/demo_질문답변.webm` | 이상치 질문·답변과 재테스트 영상 (실제 사용 속도) |
| `dummy-data/` | 화면에 올려 볼 표본 파일 (프로그램, 마스터, 재고, 답변) |

## 화면 구성

| 구분 | 화면 | 쓰는 사람 | 하는 일 |
| --- | --- | --- | --- |
| 검증 실행 | S1 내 프로그램 버전 | 현업 사용자 | 고친 pipeline.py 등록 |
| | S2 검증 실행 | 현업 사용자 | 버전·입력 일자·파라미터를 골라 실행 |
| | S3 검증 결과 | 현업 사용자 | 건수 차이, 업무 규칙, 이상치, 수량이 달라진 상품 확인 |
| | Q 질문·답변 | 현업 사용자, 바이어 | 이상치 질문 보내기, 답변 받기, 재테스트 |
| | S4 운영 반영 승인 | IT혁신팀 | 회귀 테스트 결과 확인 후 승인·반려·되돌리기 |
| 운영 실행 | S5 마스터 데이터 | MD | 양수도 그룹, 제외·전용 SKU 올리기 |
| | S6 입력 상태 | S&OP 담당자 | 입력 묶음 확인, 재고 파일 올리기, 실행 계속 |
| | S7 운영 실행·결과 | S&OP 담당자 | 오늘 실행, 결과 확인, 승인 |
| | S8 결과 내려받기 | S&OP 담당자 | ERP 업로드 파일 받기 |
| 기록 | 실행 이력 | 전체 | 실행 기록 조회 |

## 사용 흐름

### 1. 검증 실행 — 고친 프로그램을 등록해 돌려 본다

**1.** S1 내 프로그램 버전. 운영본 v0.3 하나가 운영 중이다

![01_S1_처음.png](walkthrough_mvp/01_S1_처음.png)

**2.** 문법 오류가 있는 파일은 등록이 거절되고 오류 위치가 보인다

![02_S1_문법오류_거절.png](walkthrough_mvp/02_S1_문법오류_거절.png)

**3.** 수정본이 V-002로 등록된다. 올린 파일은 바꾸거나 지울 수 없다

![03_S1_등록됨.png](walkthrough_mvp/03_S1_등록됨.png)

**4.** S2 검증 실행. 버전, 입력 일자를 고르고 최소보장일수를 5에서 4로 바꿔 본다 (이 실행에만 적용)

![04_S2_검증실행_설정.png](walkthrough_mvp/04_S2_검증실행_설정.png)

**5.** 실행하면 입력 검증 → 프로그램 실행 → 규칙 확인 → 기록 저장 순으로 진행된다

![05_S3_실행중.png](walkthrough_mvp/05_S3_실행중.png)

**6.** S3 검증 결과. 운영 버전과의 건수 차이, 규칙 5개, 이상치 6건, 달라진 SKU가 보인다

![06_S3_검증결과_이상치.png](walkthrough_mvp/06_S3_검증결과_이상치.png)

**7.** 검증 실행 결과는 TEST_가 붙은 이름으로만 내려받아진다

![07_S3_TEST_내려받기.png](walkthrough_mvp/07_S3_TEST_내려받기.png)

### 2. 이상치 질문·답변과 재테스트 — 이상한 결과를 담당자에게 묻고 답을 반영해 다시 돌린다

**8.** 질문·답변. 이상치마다 물어볼 사람(프로그램 작성자, 점별 바이어)과 질문이 자동으로 만들어진다

![08_Q_질문목록_생성.png](walkthrough_mvp/08_Q_질문목록_생성.png)

**9.** 질문 목록을 파일로 내려받거나 받는 사람에게 보낸다. 보낸 뒤에는 답변 칸이 열린다

![09_Q_보냄_답변대기.png](walkthrough_mvp/09_Q_보냄_답변대기.png)

**10.** 답변 방법 1: 받는 사람이 화면에서 직접 고르고 적는다 (인천공항T1 바이어의 답변)

![10_Q_화면에서_답변.png](walkthrough_mvp/10_Q_화면에서_답변.png)

**11.** 답변 방법 2: 답변이 적힌 파일을 올린다. 쓸 수 없는 답변 선택이 있으면 그 줄을 알려 준다

![11_Q_답변파일_선택오류.png](walkthrough_mvp/11_Q_답변파일_선택오류.png)

**12.** 답변이 모두 들어오면 반영 계획이 나온다: 파라미터 변경, 이동 제외, 사유 확인, 프로그램 수정 필요

![12_Q_답변완료_반영계획.png](walkthrough_mvp/12_Q_답변완료_반영계획.png)

**13.** 답변을 반영한 재테스트 결과. 이상치마다 해소, 확인됨, 남음이 표시되고 첫 테스트와의 차이가 보인다

![13_S3_재테스트_결과.png](walkthrough_mvp/13_S3_재테스트_결과.png)

### 3. 차단과 운영 반영 — 잘못된 입력과 결과는 막히고, 확인된 버전만 운영에 반영된다

**14.** 부분 추출된 0813 입력을 고르면 입력 검증에서 멈춘다. 빠진 카테고리 이름이 보이고 결과 파일은 없다

![14_S3_0813_입력실패.png](walkthrough_mvp/14_S3_0813_입력실패.png)

**15.** 규칙을 어기는 결과가 나오면 상태가 규칙위반이 되고 운영 반영 요청이 막힌다

![15_S3_규칙위반.png](walkthrough_mvp/15_S3_규칙위반.png)

**16.** S4 운영 반영 승인. 재테스트까지 마친 버전을 요청하면 0812 기준 입력으로 회귀 테스트가 돈다

![16_S4_회귀결과.png](walkthrough_mvp/16_S4_회귀결과.png)

**17.** 승인하면 수정본이 운영 버전이 되고 이전 운영본은 보관된다. 되돌리기도 할 수 있다

![17_S4_승인됨.png](walkthrough_mvp/17_S4_승인됨.png)

### 4. 운영 실행 — 오늘의 결과를 만들고 ERP 업로드 파일을 받는다

**18.** S5 마스터 데이터. 시트가 빠진 파일은 거절되고 빠진 시트 이름이 보인다

![18_S5_시트누락_거절.png](walkthrough_mvp/18_S5_시트누락_거절.png)

**19.** 온전한 파일은 새 버전(v6)으로 보관된다. 이전 버전은 남아 있다

![19_S5_마스터_새버전.png](walkthrough_mvp/19_S5_마스터_새버전.png)

**20.** S6 입력 상태. 판매예측과 코드표는 자동 수집됐고, 재고는 파일을 기다린다

![20_S6_입력상태_처음.png](walkthrough_mvp/20_S6_입력상태_처음.png)

**21.** 부분 추출된 재고 파일을 올리면 실제로 파일을 읽어 빠진 카테고리를 알려 주고 실행을 막는다

![21_S6_부분추출_실패.png](walkthrough_mvp/21_S6_부분추출_실패.png)

**22.** 전체 추출 파일을 올리면 컬럼 72개, 카테고리 6개, 점 10개를 통과하고 입력 묶음이 준비된다

![22_S6_전체추출_준비됨.png](walkthrough_mvp/22_S6_전체추출_준비됨.png)

**23.** S7 운영 실행. 공헌이익 파일이 오래되어 확인대기로 멈춘다. 담당자가 확인해야 진행된다

![23_S7_확인대기.png](walkthrough_mvp/23_S7_확인대기.png)

**24.** 실행이 끝나면 요약 건수, 전일 대비 차이, 규칙 5개, 구간별 걸린 시간이 보인다

![24_S7_운영결과.png](walkthrough_mvp/24_S7_운영결과.png)

**25.** S8 결과 내려받기. 승인 전에는 ERP 업로드 파일을 받을 수 없다

![25_S8_승인전_막힘.png](walkthrough_mvp/25_S8_승인전_막힘.png)

**26.** 담당자가 결과를 확인하고 승인한다

![26_S7_승인됨.png](walkthrough_mvp/26_S7_승인됨.png)

**27.** 승인 뒤에는 ERP 업로드 파일이 올리는 순서(온→오프, 양수도, 오프→온)대로 놓인다

![27_S8_ERP파일_순서.png](walkthrough_mvp/27_S8_ERP파일_순서.png)

**28.** 실행 이력. 재테스트와 회귀 실행까지 누가 언제 어떤 버전과 입력으로 실행했는지 모두 남는다

![28_실행이력.png](walkthrough_mvp/28_실행이력.png)

## 이상치 질문·답변에서 협의할 정책

| 협의할 것 | 현재 동작 |
| --- | --- |
| 무엇을 이상치로 볼 것인가 | 과다 이동, 이동 건수 이상, 미충전, 전일 대비 급변, 운영 버전과의 차이 |
| 누구에게 물을 것인가 | 프로그램·설정은 작성자, 점의 수요·사정은 그 점의 바이어 |
| 질문 문안 | 이상치 종류별로 정해진 문안. LLM으로 문안을 만드는 방안은 협의 대상 |
| 보내고 받는 방법 | 화면에서 직접 답하거나, 질문 목록 파일(CSV)에 답을 적어 다시 올린다 |
| 답변 분류 | 정상 / 이동 제외 / 파라미터 조정 / 로직 수정 / 기타 |
| 재테스트 반영 | 정상은 사유를 기록하고 이상치에서 제외, 이동 제외는 그 상품을 빼고 실행, 파라미터 조정은 제안값으로 실행, 로직 수정은 새 버전 등록 후 재테스트 |
| 이동 제외의 지속 | 그 재테스트에만 적용. 계속 적용하려면 MD가 제외·전용 SKU 마스터에 반영 |
| 바이어의 접속 | 화면에 바이어 역할이 있다. 파일이나 메일로만 주고받는 방식도 가능하다 |
| 운영 실행에 적용 | 현재는 검증 실행에만 있다 |
